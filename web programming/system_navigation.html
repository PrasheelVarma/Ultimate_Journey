Flutter Navigation Guide 🗺️

Flutter's navigation system is simple and flexible, allowing you to move between different screens (or "routes") in your app. The primary way to handle this is with the Navigator widget. Think of the Navigator as a stack of pages, where the top page is the one currently visible. When you navigate to a new screen, you're pushing it onto the stack. When you go back, you're popping it off.

1. Basic Navigation

The most common method is using Navigator.push to move to a new screen and Navigator.pop to return. This is ideal for straightforward forward-and-back navigation.

Pushing a New Screen

To navigate to a new screen, you'll use Navigator.push and a MaterialPageRoute. This route widget creates a platform-specific transition animation (e.g., sliding from the right on Android, a more subtle fade on iOS). 

// Let's say we have a ScreenA and want to go to ScreenB.

// In your button's onPressed() method:
onPressed: () {
  Navigator.push(
    context,
    MaterialPageRoute(builder: (context) => ScreenB()),
  );
}

The builder property of MaterialPageRoute is a function that returns the widget for the new screen. The context is a crucial part of Flutter and represents the location of a widget in the widget tree.

Popping Back

To return to the previous screen, you'll call Navigator.pop. This action removes the current route from the stack. 

// In a button or an `onPressed` handler in ScreenB:
onPressed: () {
  Navigator.pop(context);
}

2. Named Routes

For more complex applications with many screens, using named routes is a better approach. It makes the code cleaner and easier to manage by giving each screen a unique string name.

Setup

First, define your named routes in the MaterialApp widget in your main.dart file. The routes property is a map where the key is the route name (a String) and the value is a function that returns the widget for that screen. 

// In your MaterialApp widget
MaterialApp(
  title: 'Named Routes Demo',
  initialRoute: '/', // The default route when the app starts.
  routes: {
    '/': (context) => const HomeScreen(),
    '/details': (context) => const DetailsScreen(),
  },
);

Navigation

Once set up, you can navigate by using Navigator.pushNamed. 

// Navigate to the '/details' screen
onPressed: () {
  Navigator.pushNamed(context, '/details');
}

Returning with Named Routes

To go back, you still use Navigator.pop, as the named route system is just an abstraction built on top of the same Navigator stack.

3. Passing Data Between Screens

Often, you'll need to send data from one screen to another. With named routes, this is typically done using the arguments property of pushNamed. The data is then accessed on the receiving screen using ModalRoute.of(context)!.settings.arguments.

Sending Data

// From HomeScreen to DetailsScreen
onPressed: () {
  Navigator.pushNamed(
    context,
    '/details',
    arguments: {
      'title': 'The Final Frontier',
      'description': 'A new world awaits you.',
    },
  );
}

Receiving Data

// In your DetailsScreen widget's build method
@override
Widget build(BuildContext context) {
  // Extract the arguments
  final args = ModalRoute.of(context)!.settings.arguments as Map<String, String>;
  final title = args['title'];
  final description = args['description'];

  return Scaffold(
    appBar: AppBar(
      title: Text(title!),
    ),
    body: Center(
      child: Text(description!),
    ),
  );
}

4. Navigation with GoRouter

For a more robust and scalable solution, especially in larger applications, using a package like go_router is highly recommended. It offers a declarative approach to navigation, handles deep linking, and makes complex routing scenarios much simpler.

Installation

Add go_router to your pubspec.yaml file. 

dependencies:
  flutter:
    sdk: flutter
  go_router: ^11.0.0

Setup

Define your routes in a GoRouter object. 

final GoRouter _router = GoRouter(
  routes: <RouteBase>[
    GoRoute(
      path: '/',
      builder: (BuildContext context, GoRouterState state) {
        return const HomeScreen();
      },
    ),
    GoRoute(
      path: '/details',
      builder: (BuildContext context, GoRouterState state) {
        return const DetailsScreen();
      },
    ),
  ],
);

Wrap your MaterialApp with MaterialApp.router and use your _router object. 

MaterialApp.router(
  routerConfig: _router,
);

Navigation

You can navigate by name or by path using the context. 

// Navigate by path
onPressed: () {
  context.go('/details');
}

// Navigate by name (if you've named your routes)
onPressed: () {
  context.goNamed('detailsRouteName');
}
